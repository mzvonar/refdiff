## Key facts / decisions

- **A finding can be EXPLAINED (2026-09-04).** `ignore.explain: [{ types, region | within: { role },
  text?, cause, reason }]` keeps the finding reported with its severity, tags it
  `explained: { cause, rule }`, groups it in the run line, and leaves it OUT of the verdict.
  `types` is the SAFETY: name only what the cause can physically produce, so `color`, `typography`,
  `border` and `text-content` in the same region stay unexplained and still fail. **It does not
  lapse by itself** the way an `accepted` rule does, so two audits watch it: every run prints any
  cause whose count MOVED against the previous run, and `refdiff summary` names any declared cause
  that matched nothing anywhere in the set. The delta is the backstop — an explained finding is
  still in it.
- **`contentsOf` (2026-09-03).** The artboard excuse names the ELEMENT, fires every run, follows a
  panned canvas, and skips a container the frame does not contain. Text is never excused (the comp
  draws its badges over the artboard).
- **The app diverges from the comps deliberately in two places, both decided:** the pane INSETS
  bound the fit and the focus zoom (the comps size from the full pane), and a comment belongs to the
  pane it was drawn on (the comps draw ordinary demo comments on both panes).
- **The comps are CONTENT-box; the app is border-box.** Every app rule copying a fixed size from a
  bordered comp box is written as the comp's number plus the border (`calc(44px + 1px)`).
- **A green pair proves the STATE matches the comp, never that a user can REACH it.** Every pair
  pins the URL and steps that put the app in that state; the default a user actually gets is
  measured by no pair unless one pins it.
- Source-of-truth pointers: `refdiff.bindings.md` (paths, ports, the measured baseline, the traps —
  READ IT FIRST), `skills/refdiff/SKILL.md` (the loop), `docs/architecture.md` → Open decisions,
  `docs/handoff-2026-09-03.md` (sessions 17–20 long form).

## Env gotchas

- **No backticks anywhere in `render.ts`'s client block, comments included** — it lives in a TS
  template literal, and one backtick is an `Unclosed comment`-class build break. Bit me this session.
- **The manifest parser WHITELISTS `ignore` keys** (`readIgnore`). A new policy field it does not
  read is dropped in SILENCE — core, policy and manifest can all be correct while five pairs of six
  do not move. Every new field needs a row in `manifest.test.ts`.
- **A server restart needs the port to actually free.** Kill, poll until the port refuses, then
  start — otherwise the new process dies with EADDRINUSE and the OLD one keeps answering 200, so
  readiness checks lie. Verify by CONTENT (grep the served shell for a string you just added).
- **`pgrep -f` / `pkill -f` match the shell running them.** Kill by PID.
- **Pin the fixture clock before measuring**, regenerate without `--now` afterwards, never commit
  `--now` output.
- **A `python3` heredoc that fails does NOT stop a following `git commit`** unless they are in one
  `&&` chain. That shipped a one-of-four docs fix to main this session.
- **Compare `dist/render.js`'s mtime against `src/render.ts` before believing any measure.**
- A change to the matcher, a role name or the view RE-KEYS findings, so the delta churns exactly
  once and the next run is clean. Say so rather than chasing it.
- `out/` is gitignored; the served app WRITES into what it serves, so the measured instance is
  `--read-only` and `git checkout fixtures/` undoes an accident.
