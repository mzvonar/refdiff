## What's DONE (session 5 — pixel channel, plan item 2)

- `geometry.ts` (pure): `toDesignNative(box, alignment, dpr)`,
  `toImplNative`, `clampBox`, `padBox`, `scaleBox` — extracted from
  `package-for-model.ts`, shared with the pixel channel.
- `pixel/diff.ts` (effectful edge, sharp + pixelmatch v7 `includeAA:false`,
  threshold 0.1): per `ElementMatch`, crop the design element through the
  inverse alignment at design native res, resample onto the impl crop's
  pixel grid, compare at every integer offset within ±`shift` (default 2
  impl native px) and keep the best → `MatchDiff { mask, diffRatio,
  diffPixels, dpr }`. Elements compared inside their OWN boxes, so position
  findings don't fail pixels. `writeDiffMask` paints all masks on an
  impl-sized transparent canvas → `artifacts.diffMask` (`diff-mask.png`).
- `pixel/cluster.ts` (pure): 8-connected components with `gap`/`minSize` →
  `Cluster { box, pixels }`, `unionBox`.
- `pixel/checks.ts` (pure): `runPixelChecks(diffs, structural)` → one
  `pixel-region` RawFinding per eligible match (box = union of clusters in
  impl CSS px, designBox = same relative region, `actual: { diffRatio,
  diffPixels, clusters }`), severity by Argos thresholds 5% / 15% / 30%,
  ≥12 differing px. `isPixelEligible`: skips text elements (default), boxes
  < 16 CSS px, data slots, and pairs with a structural size/color/
  typography/radius/border/spacing finding. `lowConfidenceFinding` for the
  gate (confidence < 0.5 → one boxless minor finding).
- `structural/checks.ts`: `finalize` + `RawFinding` exported — both
  channels are numbered together. CLI: `runTypedChecks → diffMatches →
  runPixelChecks → finalize → applyPolicy → aggregate → package`,
  `--no-pixels`. 76 tests (cluster, thresholds, gate, no-duplication,
  eligibility, geometry, and an effectful diff test on synthetic PNGs
  through a ×0.94 resample).
- `@blazediff/agent` evaluated and declined as a dependency; `regions[]`
  protocol adopted as reference (architecture.md "Open decisions").

### Learnings (session 5)

- **Pixel diff at scale ≠ 1 is edge-phase noise for small things.** Measured
  on doc-detail (design resampled ×0.94, 50 matched boxes, variants
  threshold 0.1/0.2 × blur 0/1 × shift 0–3): identical text 10–40%
  differing pixels, identical 10–14px icons/dots 12–16% even with shift 2;
  blur helped some rows and hurt others. Shift 2 cut icon noise roughly in
  half; nothing brings small glyphs under 5%. Hence: skip text (element
  data is exact for it) and anything < 16px. A 40×40 identical box through
  the same resample lands at 2.4% — under the minor floor.
- The very high ratios (30–100%) were all on pairs that already had a
  structural color finding (the #2c2419 ink) — the no-duplication rule is
  what keeps the channel quiet, not the thresholds.
- **doc-detail with pixels on: 0 pixel-region findings, 57/100 structural
  unchanged.** The handoff's expected icon/badge/placeholder hits are not
  pixel-only: header icons are 14px (below the floor, and visually
  identical), the badge is text with a color finding, the striped
  placeholder is a design-only element. The channel earns its keep on
  images/illustrations/gradients ≥16px — none of which doc-detail has.
- NCC refinement stays unbuilt: the residue is sub-pixel phase, absorbed by
  the shift search; there is no visible translation residue to correct.

## What's DONE (session 4 — aggregation, plan item 1b)

- `structural/aggregate.ts`: pure `aggregate(findings, { minInstances,
  deltaTolerance })`. Groups by `(type, canonical expected/actual)` for
  color/typography/border-radius/border/spacing; position/size cluster on
  the same shift (dominant axis ±2px of the cluster mean, other axis up to
  half the shift; greedy pass + merge pass so an early outlier cannot seed
  its own cluster). ≥3 members → one finding: max severity, message "×N",
  `Finding.instances` + `Finding.members[] { designBox?, implBox? }`
  (primary = first member = the `designBox`/`implBox`). Output re-sorted by
  severity (stable) and renumbered. Missing/extra/text-content never
  aggregate. Input never mutated.
- Pipeline: `runTypedChecks → applyPolicy → aggregate → packageForModel`;
  CLI `--no-aggregate`; list prints `[n] ×N …` and "covering M instances".
- Overlay draws one mark per member (same number); crops for the primary
  only; `findings.json` keeps every member box.
- `doc-detail`: 100 → 57 findings covering 100 instances (8 critical /
  22 major / 27 minor), 22 data-slot suppressions unchanged.
- **Still-loading guard** (`adapters/storybook.ts`): the mount predicate
  ignores Storybook chrome (`body.sb-show-preparing-*`, `.sb-* ` wrappers)
  and, for overlay stories, looks for visible DESCENDANTS beside the root
  (the Radix portal wrapper is 0px tall). On timeout, a body still in the
  preparing state is a typed `still-loading` CaptureError (new variant),
  otherwise `blank-render` as before.
- **Storybook auto-start** (`adapters/storybook-server.ts`,
  `ensureStorybook`): `--storybook-dir <dir>` / `$VC_STORYBOOK_DIR` — when
  nothing answers at `--storybook-url`, run `pnpm exec storybook dev -p
  <port> --ci` there (no browser tab, no prompts), wait until reachable
  (typed `storybook-start-failed` otherwise), stop the process group after
  the run. A Storybook you started yourself is reused and left alone;
  `--storybook-open` lets the auto-started one open its tab.

- After aggregation the remaining doc-detail list is the plan's target:
  8 missing (category row, Popis + description, second date, one amount,
  "Zobraziť 1 ďalší návrh"), 2 extras (source line, "78 %"), ink ×15,

## What's DONE (session 3 — ignore policies, plan item 1)

- `policy.ts`: serializable `IgnorePolicy { textPatterns (regex sources),
  roles, regions (impl-space boxes), scope, dataSlots }`; pure
  `applyPolicy(findings, policy) -> { kept, suppressed }` — kept
  renumbered `f1..`, suppressed `s1..` tagged `suppressedBy` + `rule`.
  `findings.json` carries `suppressed` and `policy`; verdict is over
  `findings` only. `mergePolicies` = manifest pair policy ⊕ CLI flags.
- `DcHtmlSource.scope` + `adapters/scope.ts`: adapter captures an inner
  node instead of the artboard frame. Explicit selector must exist
  (`scope-not-found` typed error); fallback = frame's largest child by
  area (≥96² px, pure `pickLargestChild`); childless frame → frame itself.
  `Capture.scope { mode, selector, candidates }` is recorded and echoed
  in `findings.json` `design.scope`. Chrome (label strip, chips, notes)
  is therefore never extracted or matched at all.
- Matching pass 3 (`via: "slot"`): leftover TEXT elements pair
  width-blind (|Δx|+|Δy|+|Δh| ≤ 40) — a shrink-wrapped design value vs a
  column-width impl cell is the same slot showing other data.
  `ElementMatch.via` = text | geometry | slot.
- Data-slot rule: `dataSlots: true` (CLI default, `--no-data-slots` to
  disable) suppresses `text-content` on matched pairs; `size` on a
  text-differing pair compares HEIGHT only (width is content). All other
  checks still run on the pair.
- Extraction fixes forced by the corpus: text leaves measured by
  glyph-ink box (Range client rects), pill radii clamped to
  min(w,h)/2, viewport-filling textless leaves → role `backdrop`
  (presence findings minor). `Finding.role` added so policies key on it.
- CLI: `--manifest <file>` (uctoinak `manifest.mjs` shape; `export const
  manifest` or default; optional `ignore` per pair and `design.scope`),
  `--pair a,b` filter, live-app entries listed as skipped; `--scope`,
  `--ignore-text <regex>` (repeatable), `--no-data-slots`. Exit 2 if any
  capture error, 1 if any FAIL, else 0. Pure `manifest.ts` validates.

### 3. Hygiene / small checks ← DO FIRST (docs/plan-next.md item 3)

Goal: close the gaps in the structural channel's typed checks and give the
model loop what it needs before the skill is drafted. Baseline to protect:
doc-detail = 57 findings / 100 instances, 22 data-slot suppressions, 0
pixel findings; every new finding must be verifiable in the crops.

1. **`border` check** (`structural/checks.ts` `pairFindings`) — extraction
   already emits `style.borderWidth` + `style.borderColor` for leaves
   (`adapters/extract.ts` ~L131; top side only, `border-style: none`
   skipped). Report `type: "border"` when width differs > 0.5px or color
   ΔE2000 ≥ `colorDeltaEMinor`; severity minor unless width goes 0↔N or ΔE
   ≥ major. Add to `TYPE_ORDER`. Aggregation already keys `border` on
   exact `(expected, actual)`. Test in `checks.test.ts`. Run doc-detail —
   the six radius findings are on bordered pills/buttons, so expect
   border findings there only if genuine (check crops).
2. **`spacing` check** — the open design question first: extraction emits
   leaves + text-bearing containers ONLY (`walk`, L175–181), so there is
   no container with `gap`/`padding` to compare and `ElementNode.style.gap
   / padding` are never filled. Decide in `architecture.md` "Open
   decisions": (a) emit flex/grid containers with `gap` + `padding` as
   `role: "container"` nodes (kept out of γ-matching by role, matched by
   child-set identity instead), or (b) derive spacing from matched
   siblings: for consecutive matched leaves sharing a parent, compare the
   inter-box gap design vs impl (no extraction change, pure over
   `MatchResult`). Recommend (b) first — it needs no adapter change, uses
   only data we have, and the action-row / lower-half shifts on doc-detail
   would then read as ONE spacing finding on the row above instead of
   position aggregates. Tolerance 2px, severity minor / major at > 8px.
   Tests on synthetic matches.
3. **Relative verdict** — `ComparisonReport.delta { previousRun, resolved,
   introduced }` is already typed (`types.ts`). Pure
   `diffReports(prev, next)` in `package/delta.ts`: identity of a finding
   = `(type, role, canonical expected/actual, nearest design box within
   5px)` — NOT `id`/`mark`, which renumber. CLI: when `--out` already holds
   a `findings.json`, read it BEFORE overwriting, attach `delta`, print
   "+N introduced / −M resolved". Regression guard for the skill later.
4. **`inspect` subcommand** (`cli.ts`, planned in USAGE) — `inspect <run-dir>
   --finding f12 [--zoom 4] [--pad 24]` writes zoomed crop pairs;
   `--sample x,y` prints the RGBA + nearest element on both sides. Reuse
   `geometry.ts` + the crop code in `package-for-model.ts` (extract
   `cropTo` into `package/crop.ts` first). Only build once the model loop
   actually consumes reports — otherwise skip to Figma adapter.

Done when: doc-detail lists border/spacing findings only where the crops
confirm them, re-running the same pair yields `delta: { resolved: [],
introduced: [] }`, and structural counts otherwise stay at 57/100.

## Key facts / decisions

- **The model is never the comparator** — deterministic findings gate
  everything. Full rationale + citations: `docs/research.md`.
- Decisions locked with Mato: one repo / two packages; public GitHub
  (mzvonar/visual-compare); core = CLI + library wrapped by a thin skill
  (MCP maybe later); both Figma and `.dc.html` ref sources supported
  (dc.html first — richest data); **FP paradigm mandatory**: pure
  composable stages, immutable data, typed `Ok | Err` results, effects
  only at adapter edges, every stage independently importable. Plain
  typed functions for now (no Effect library) — revisit if noisy.
- Reference implementations to port from (don't reinvent):
  `~/Development/uctoinak-bmad/tools/design-compare/` (renderer, capture,
  compose, skill with "measure don't eyeball" checklist) and
  `~/Development/inno-workspace/repos/population-registry/frontend/ds/tooling/visual/`
  (Figma REST layer `figma-api.mjs` with cooldown handling, annotator UI
  + state machine, `pngsample.mjs`/`pnggrid.mjs` zero-dep pixel readers).
- Blueprint: GVT (ICSE 2018) — leaf boxes, γ-distance matching, typed
  per-pair checks, scoped pixel diff; calibration constants 5px / 20% /
  85% come from that paper.
