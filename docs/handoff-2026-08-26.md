### Learnings (session 8)

- **`pnpm dev:e2e` alone is NOT the test app**: `dotenv -e .env.test` loses
  to `.env.local` (Next's own env loading) — it came up on :3000 and wrote
  `__test__owner` into the DEV Supabase DB. Use `serve-live.sh`, which
  exports the test `DATABASE_URL`/ports explicitly (that is the "hermetic-e2e
  fix" its comments mention). Check `docker ps` first: the test Postgres is
  `uctoinak-bmad-postgres-test-1` on :54330.
- **The app's not-found page is a soft 404** (307 → `/app/...` → 200 with
  "Stránka sa nenašla"), so `http-error` never fires for page routes — the
  content-level `classifyPage` is the layer that catches it. `http-error`
  is real only for API routes.
- **Alignment confidence 0.00 on the live pair** is expected with the empty
  seed (no shared unique texts beyond the heading); the viewer still lines
  the pages up through the normalization scale. A documents seed for the
  design-compare live pairs (matching the comp's rows) is what makes the
  live corpus useful — that is a uctoinak-bmad task, not a harness one.
- Finding boxes (`designBox`/`implBox`) are BOTH in impl CSS px (the
  aligned frame), so the viewer draws them in one world layer per pane and
  only the PNGs need per-side transforms — the marks land on the design
  image exactly because the design PNG is projected through the same
  `Alignment` (`geometry.ts` inverse). Keep that invariant when adding
  annotations.
- zsh does not word-split `$VAR` — use arrays (`"${D[@]}"`) in shell
  helpers, or the CLI reports `ERR_PARSE_ARGS_UNKNOWN_OPTION`.
- A raw U+2028/U+2029 inside a regex literal is a line terminator for tsc
  ("Unterminated regular expression literal") — write `\u2028`.

## What's DONE (session 6 — hygiene checks, plan item 3)

- **`border` check** (`structural/checks.ts` `pairFindings`): width delta
  > 0.5px or color ΔE2000 ≥ 2.5 → `type: "border"`, `expected/actual {
  borderWidth, borderColor? }`; major when a border appears/vanishes or
  ΔE ≥ 8, else minor. A transparent border (`rgba(0,0,0,0)`) counts as no
  border (both in extraction and defensively in the check). In `TYPE_ORDER`.
- **`spacing` check** (`spacingFindings`, pure over `MatchResult`; decision
  in architecture.md "Open decisions"): for each matched pair the nearest
  neighbour below / to the right — nearest among ALL elements of a side,
  unmatched included, and adjacent on BOTH sides — gives a design gap and an
  impl gap; |Δ| > 2px → finding (major > 8px), box = union of the two
  elements, `expected/actual { gap, axis }`. Design gaps > 64px, negative
  gaps and horizontal gaps next to data slots are skipped. Aggregation
  treats spacing as metric: clusters on Δgap per axis (`aggregate.ts`).
- **Relative verdict**: pure `package/delta.ts` — `identityKey` (type, role,
  canonical expected/actual), `boxDistance` (per edge), `diffFindings`
  (greedy one-to-one, 5px), `diffReports(prev, next)` → `delta {
  previousRun, resolved (prev ids), introduced (new ids) }`.
  `packageForModel({ previous })` attaches it; the CLI reads the run dir's
  `findings.json` at the START of `runPair` (malformed/absent → no delta)
  and prints `delta vs <iso>: +N introduced / −M resolved (introduced: …)`.
- **Decoration hoisting** (`adapters/extract.ts` `decorationSource`): a
  leaf painting no bg/border/radius takes them from the nearest ancestor of
  which it is the only child through textless wrappers; radius clamped to
  that ancestor's rect. Border/radius are compared only between comparable
  boxes (text pairs, or size within tolerance).
- `inspect` NOT built — nothing consumes reports yet (plan §3.4 condition).
- 94 tests (border ×6, spacing ×6, delta ×6). Exports in `index.ts`.

### Learnings (session 6)

- **"Nearest matched neighbour" is wrong; "nearest element, then require it
  to be matched and adjacent on the impl side too" is right.** First cut
  reported `28. 7. 2026 → Návrhy spárovania` 56 → 20px — the design has the
  missing `Popis` row in between, so the gap "shrank" only because content
  is missing (already critical findings). Same for `Dátum vystavenia →
  Zúčt. obdobie` where the design's date value is missing.
- **Gaps > ~64px are layout distance, not spacing**: header badge →
  footer button (664px) and 17 header elements → a badge 72px lower showed
  up as spacing before the cap. Negative gaps = swapped order (position).
- **The leaf-granularity gap bites decoration checks first.** `⋯` is
  `<button class="border rounded"><span>⋯</span></button>` in the impl but
  a bordered `<div>⋯</div>` in the comp; the radio is a bordered circle
  with an inner 8px dot in the design and a childless circle in the impl.
  Without hoisting: "no border, design has one" ×2, "border the design
  does not have" ×2, radius 0 vs 8 — all false in the crops. With it: two
  of the six baseline radius findings turned out to be the same artefact
  and resolved; `⋯` is now a genuine 12 vs 8px pill radius ×3; the `2`
  badge's background (beige vs the design's red) became visible.
- doc-detail after session 6: 57/100 → 60/122 — +5 spacing (label→value
  gap 2 → 12px ×3, header→tabs 28 → 31px ×14, subtitle→amount 7.5 → 14px
  ×3, two 9.4 → 12px action-row separators), +1 minor border color (ΔE 5.6
  on `Spárovať manuálne`), +1 badge bg, −3 radius artefacts. Elements below
  the 740px impl viewport (action row, `Spárovať manuálne`) get no crops —
  pre-existing; the model must read `expected/actual` for those.
- The delta tooling paid for itself immediately: every tuning iteration
  was read off `+N introduced / −M resolved` instead of diffing lists.

### Learnings (session 5)

- **Pixel diff at scale ≠ 1 is edge-phase noise for small things.** Measured
  on doc-detail (design resampled ×0.94, 50 matched boxes, variants
  threshold 0.1/0.2 × blur 0/1 × shift 0–3): identical text 10–40%
  differing pixels, identical 10–14px icons/dots 12–16% even with shift 2;
  blur helped some rows and hurt others. Shift 2 cut icon noise roughly in
  half; nothing brings small glyphs under 5%. Hence: skip text (element
  data is exact for it) and anything < 16px. A 40×40 identical box through
  the same resample lands at 2.4% — under the minor floor.
- The very high ratios (30–100%) were all on pairs that already had a
  structural color finding (the #2c2419 ink) — the no-duplication rule is
  what keeps the channel quiet, not the thresholds.
- **doc-detail with pixels on: 0 pixel-region findings, 57/100 structural
  unchanged.** The handoff's expected icon/badge/placeholder hits are not
  pixel-only: header icons are 14px (below the floor, and visually
  identical), the badge is text with a color finding, the striped
  placeholder is a design-only element. The channel earns its keep on
  images/illustrations/gradients ≥16px — none of which doc-detail has.
- NCC refinement stays unbuilt: the residue is sub-pixel phase, absorbed by
  the shift search; there is no visible translation residue to correct.
