## What REMAINS (in order)

### 1. Pipeline data types + Result union ← DO FIRST
Extend `packages/core/src/types.ts` (or a `pipeline.ts`) with the
inter-stage types from architecture.md: `SourceConfig`, `RefDescriptor`,
`Capture` (png buffer/path + width/height + dpr + element tree + typed
error variants), `Pair`, `NormalizedPair`, `AlignedPair`, `ElementMatch`,
and a plain `Result<T, E>` union. Keep stages pure functions; effects
only in adapters.

### 2. `.dc.html` design adapter ← DO SECOND
`packages/core/src/adapters/`. Port the working parts of
`~/Development/uctoinak-bmad/tools/design-compare/lib/render-design.mjs`
and `lib/browser.mjs` (static `serveDir` with path containment, frame
addressing by `[id]` / `[data-screen-label]`, `document.fonts.ready`,
hydration probe `!/\{\{…\}\}/`). New on top: extract the DOM element tree
(leaf boxes via `getBoundingClientRect` + computed styles per
`ElementNode.style`) in the same page context — the `.dc.html` source
gives DOM ground truth, which is why this slice starts here. Hydration/
font failure = typed error, never a silent screenshot.

### 3. Storybook impl adapter
Port the storybook path of
`uctoinak-bmad/tools/design-compare/lib/capture-app.mjs`
(`iframe.html?id=<storyId>&viewMode=story`, `#storybook-root` readiness,
`sb-show-errordisplay` detection) + the same DOM element extraction +
stabilization (animations-off CSS injection, capture-until-stable).
Add rendered-error/blank-page content detection — "capture succeeded"
must mean "a real component rendered" (the documented 404-as-success
failure in the old harness).

### 4. Structural channel
`matchElements` (GVT γ = |Δx|+|Δy|+|Δw|+|Δh| nearest-neighbor; unmatched
→ missing/extra findings) and `runTypedChecks` per matched pair:
position/size (~5px default tolerance), color (CIEDE2000 via culori),
typography (family/size/line-height/weight), border-radius, text.
Weight severity by the human-correlation evidence: presence/position >
color > everything else (research.md §3).

### 5. Agent packaging
`packageForModel`: write `findings.json` (`ComparisonReport`), the
set-of-marks overlay (sharp composite: numbered marks at finding boxes),
and per-finding native-res crop pairs as separate files. No concatenated
side-by-side images ever.

### 6. CLI `compare` + prove on a real pair
Wire `visual-compare compare` for one manifest entry. Test corpus: the
vendored comps in `uctoinak-bmad/tools/design-compare/design-reference/`
+ its Storybook (`manifest.mjs` has 39 pairs; pick one desktop pair with
known differences). Success = findings.json lists real, correct,
actionable differences and is quiet on a matching pair.

## Key facts / decisions

- **The model is never the comparator** — deterministic findings gate
  everything. Full rationale + citations: `docs/research.md`.
- Decisions locked with Mato: one repo / two packages; public GitHub
  (mzvonar/visual-compare); core = CLI + library wrapped by a thin skill
  (MCP maybe later); both Figma and `.dc.html` ref sources supported
  (dc.html first — richest data); **FP paradigm mandatory**: pure
  composable stages, immutable data, typed `Ok | Err` results, effects
  only at adapter edges, every stage independently importable. Plain
  typed functions for now (no Effect library) — revisit if noisy.
- Reference implementations to port from (don't reinvent):
  `~/Development/uctoinak-bmad/tools/design-compare/` (renderer, capture,
  compose, skill with "measure don't eyeball" checklist) and
  `~/Development/inno-workspace/repos/population-registry/frontend/ds/tooling/visual/`
  (Figma REST layer `figma-api.mjs` with cooldown handling, annotator UI
  + state machine, `pngsample.mjs`/`pnggrid.mjs` zero-dep pixel readers).
- Blueprint: GVT (ICSE 2018) — leaf boxes, γ-distance matching, typed
  per-pair checks, scoped pixel diff; calibration constants 5px / 20% /
  85% come from that paper.
