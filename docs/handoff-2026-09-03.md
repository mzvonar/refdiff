## What REMAINS (in order)

### 1. The 14 `shape` findings — DECIDED AND DONE, 2026-09-03 (kept as §1 so §2–§4 still resolve)
Mato's framing was one line: **the comp is right.** The premise this section carried was wrong, and
the measurement is what said so — none of the three options was taken, because none of them applied:

- The comps draw a mark as a BADGE and no outline at all unless it is SELECTED (`RefDiff Comparison
  Tool.dc.html:587` findings, `:595` comments) or `highlight` is on (`:553`, `:597`, default false at
  `:380`). So the 14 were DRIFT, not data.
- "Move the fixture's comments to the comps' positions" was already true: design badge "2" x=90.62
  against impl x=90.62, Δy 0.5px. Only the outline had no counterpart.
- All 22 reported `shape` findings across the set were that one layer (the desktop-ghost's eight are
  the same four marks at 2.213×: 219.49/99.15 = 890/402 = 410/185). None was the ghost footprint.
- A `regions` entry over the canvas would have suppressed 30 of 79 reported findings on
  `compare-desktop`, 24 of them not shapes — `regions` is type- and text-blind (`policy.ts:123`).

The fix is one branch in `renderAnnMarks` (`packages/annotator/src/render.ts`): the comment outline
only while selected, with the finding layer's own `pad(box, 4)` + radius 6 — the finding layer had
followed the comps' rule since the redesign; the comment layer never did. Measured: 22 reported
`shape` findings → **0**, set 383 → **349**, six compare pairs down, both Library pairs untouched,
one run of churn (five `missing-element` design boxes the old force-pairing had HIDDEN, all with
pre-change `resolvedAt`), +0/−0 on the next run. Two limits found on the way, both recorded in
`SKILL.md`: the 24-shape cap reports ONE visual layer in halves (the app's finding-mark outlines are
still invisible — that svg is over the cap), and `fill-opacity` / `stroke-opacity` are not folded
into the reported paint, so a 12% tint reads as opaque and a mirror reads like the mark it mirrors.

### 2. Scope the artboard acceptance ← NOW FIRST
`COMPARE_IGNORE`'s `accepted` rule ("the app draws the run's design.png / impl.png") carries
`contents: true`, and that only fires when the app's artboard IMAGE is itself reported as an
`extra-element` — which happens only when the image fails to PAIR. On the ghost pairs the canvas is
panned, the images do not pair, the rule fires, and everything textless inside them is excused; on
`compare-desktop` the images DO pair, nothing fires, and the same elements are reported. Two pairs
quiet and four not, for an accident of pairing rather than a decision. **Not a `regions` entry over
the canvas** — that was this file's recommendation and §1's measurement refutes it (30 of 79 on
`compare-desktop`, 24 of them not shapes: the artboard criticals plus the badge geometry that
measured the 35px row and the paneInsets decisions; `regions` is type- and text-blind,
`policy.ts:123`). The narrow shapes are an `accepted` rule naming the artboard layer, or a role/type
scope on `regions` of the kind `textPatterns` already carries (`{ pattern, role?, types? }`).
It now also decides the GHOST: since svg extraction the footprint is a real `shape` on
`compare-mobile-toolbar-ghost` and travels suppressed inside that region (238.59×64.24 = o1's 200×48
padded by 4 at the pair's 1.147 canvas zoom), so this rule says whether the ghost is measured or
excused. Recorded in `docs/architecture.md` → Open decisions.

### 3. Comments: mirror or ghost? — DECIDED AND DONE, 2026-09-03 (ghost still unbuilt)
**Mato's rule: a comment belongs to the side on which it was clicked or dragged. It is different
from a finding — a finding is a pair, "this is here but missing there"; a comment is "I clicked here
and am commenting on this."** So the mirror is gone (`5e259f3`), and the measured reason it hurt is
below: a copy at the same coordinates on the other pane asserts a correspondence this tool exists to
test. What is LEFT of it is now two things, and both are named in §4 and here:
- the comp's demo comments 1–3 carry no `oneSide`, so it draws them on both panes and the app no
  longer answers those copies — 3 `missing-element` badges per compare pair, 4 on `compare-desktop`.
  Comp-side ask: give each demo comment the side it was made on, as its findings have.
- on a phone the canvas now shows NO comment mark while the off-pane side is up. The comps' answer
  is the ghost of a selected off-pane comment; it is still unbuilt, and it is now the only possible
  cross-pane signal rather than a nicety. Building it needs three status-coloured hatch patterns
  beside the severity ones plus the comps' point geometry; MEASURING it needs a pair whose steps
  select a comment, which needs a `data-vc-step` on the comp's comment rows.

The original section, for the record — note that its closing verdict ("the mirror itself is right",
because the comps draw an ordinary comment's badge on both panes) is the part the ruling REVERSES:
the comp doing it is now read as the comp's demo data lacking sides, not as the app's licence:
The app MIRRORS every note onto the other pane, lighter (`.marks.anns .mirror`), a deliberate

## Key facts / decisions

- **Zoom on select (`view-math.ts`, decided 2026-09-03).** Element + 70px context each side, a 60px
  floor on the element (that, not the 2.2× ceiling, is what stops a 0×0 anchor magnifying absurdly),
  cap 2.2×, zoom OUT when bigger than the pane. The pane INSETS bound the zoom as well as the
  centring — a deliberate divergence from the comps, which size from the full height and ignore
  their own bottom sheet; it also measured better (mobile ghost 93 → 89 versus 95 → 99 for a
  faithful copy). Result: desktop ghost 150 → 115, both zoom pills at 146%.
- **The pairing veto (`structural/match.ts`).** A candidate is refused when the two texts share no
  tokens, the distance is ≥ 20, AND each text occurs somewhere on the other side — positive evidence
  that both elements had a same-text partner available. Refused as a CANDIDATE (the assignment can
  still find the right partners), each pass using its own distance (γ in pass 2, position-only
  `slotGamma` in pass 3). Conservative on purpose; falsified per row against the corpus in
  `match.test.ts`.
- **A `pixel-region`'s identity is its `changeKind` + box**, never the measured ratio.
- **`delta.repaired`** names a regression whose element also had property findings resolved in the
  same run (a lost partner). A diagnosis, never a reclassification — a genuine vanish looks the same.
- **SVG extraction (`adapters/extract.ts`).** Atomic while every shape is icon-sized (≤64px) or
  there are more than 24; otherwise walked, children as `role: "shape"`, decided by the SHAPES not
  the svg's own box (a mark layer is a 1×1 px svg with `overflow:visible`). Paint maps to the HTML
  names exactly as the Figma adapter maps `fills`/`strokes`/`strokeDashes`; a paint SERVER goes to
  `backgroundImage`, captured and uncompared. `roles: ["shape"]` switches the channel off per pair.
- **A CSS class is a namespace.** The footprint is `.gfoot` because `.ghost` is the diff lab's
  superimposed design IMAGE at `opacity:0` — that collision made it paint nothing, invisibly.
- Source-of-truth pointers: `refdiff.bindings.md` (paths, ports, baseline, traps — READ IT FIRST),
  `skills/refdiff/SKILL.md` (the loop), `docs/architecture.md` → Open decisions,
  `docs/handoff-2026-09-02.md` (sessions 17–19 long form), `docs/lessons-inbox.md`.
