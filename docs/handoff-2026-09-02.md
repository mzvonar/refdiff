## Session 19 (2026-09-03) — four harness improvements the ghost run paid for

Every one of these came out of session 18's own friction, and each carries the measurement that
justified it. Core changes, so they touch every pair: the two ghost pairs churned once and settled
to `+0/−0`; the other six did not move.

**1. The matcher refuses a pairing it can PROVE wrong** (`structural/match.ts`,
`unrelatedPairing`). Geometry alone pairs a rail badge "6" with a prop line "element" 90 γ away when
the two lists are in a different order, then reports position, colour, typography, radius and
text-content about two unrelated elements. Measured before the fix: **12 such findings on
`compare-desktop-ghost`, 14 on `compare-mobile-toolbar-ghost`, 2 on `compare-desktop`** — and one of
them was the REGRESSION line that cost session 18 a ledger investigation.
The veto needs positive evidence, not merely differing text: no shared tokens, at least
`DEFAULT_UNRELATED_MIN_GAMMA` (20) apart, **and each text present somewhere on the other side** —
so both elements had a same-text partner available and this pair is not it. Both sides then report
missing/extra, which is what a different list order actually is.
Falsified per row against the corpus before it was written: it keeps every value slot
(`146%` ↔ `100%` at γ 0.5, a card count at γ 0, the Library's `Processing` ↔ `Clean` at γ 52 whose
word is nowhere on the impl side) and every token-sharing copy drift, and refuses the four real
mispairings. It is a CANDIDATE veto, not a dissolved winner, so the greedy assignment can still
give both elements their right partners — which is why the log reports only the refusals where both
ended unmatched: the Library pairs refuse two candidates and their outcome is byte-identical.
Each pass passes its own distance (γ in pass 2, the position-only `slotGamma` in pass 3, whose full
γ is dominated by the width difference the slot pass exists to forgive — a shrink-wrapped cell
against a column-wide one is 130 γ apart and still the same slot).
After: **14 → 0** on the toolbar ghost, **12 → 7** on the desktop ghost (the survivors are the two
documented conservative cases: `'missing'` ↔ `'×14'`, whose `×14` is nowhere on the design side, and
a same-anchor prop-label slot 9 px apart).

**2. A `pixel-region` is identified by its KIND, not its measured ratio** (`package/delta.ts`).
Its `actual` carries `diffRatio`/`diffPixels`/`clusters`, and the identity key canonicalised all of
them — so any twitch made the region resolve and re-introduce itself under its own id. Measured
twice in one session: a canvas box went 15.9% → 16.2% and the delta read `+1 introduced / −1
resolved` naming the same id in both lists. Now keyed on `changeKind` plus the box (it is textless),
which is what tells two regions apart.

**3. A regression that is really a RE-PAIRING says so** (`delta.repaired`, printed under the
REGRESSION line). Session 18's cry-wolf was not a matcher upgrade — the recorded case — but an
app-side layout change: taller rows re-paired the rail column. The signature is computable and was
present in that very delta: five findings about the text "6" resolved while one presence finding
about "6" came back. So the report now names, beside each regression, the property findings the same
run resolved about the same element text.
Deliberately a DIAGNOSIS, not a reclassification: a genuine vanish has the same shape (the element
goes, its property findings resolve with it), and quietly dropping such a regression would trade one
cry-wolf for a missed one. It fired on its first real run, on the toolbar ghost pair's
`arrow_right_alt`, naming six resolved findings.

**4. `borderStyle` — dashed against solid** (`types.ts`, `adapters/extract.ts`,
`adapters/figma-tree.ts`, `structural/checks.ts`). Session 18 shipped a whole language of dashed
footprints, pills and chips and could not verify a single dash: **403 findings said nothing about
dashedness.** The DOM side reads `borderTopStyle` where a border actually paints; the Figma side maps
`strokeDashes` — the REST field name verified against the recorded `nodes-alert-set` /
`nodes-button-fill-set` fixtures, which carry `"strokeDashes":[10.0,5.0]`, not guessed. Compared
only where BOTH sides declare it and both borders paint: an adapter that cannot read dashes leaves
it undefined rather than defaulting to `solid`, which would report every dashed comp element as
impl-only dashedness.
It reports **zero findings on the corpus** — and the positive control is what says the channel is
live rather than inert: the fresh trees carry `dashed` on both sides of six pairs (9 design / 6 impl
on the desktop ghost). It also retroactively verified session 18's own work: the ghost pill now
measures `dashed`, 1px, radius 9, at 199×30 **on both sides**, where a crop was the only evidence.

Deliberately NOT done, with the reason, so nobody re-litigates it:
- **`opacity`** — already captured by the extractor and folded into every colour it reports, so a
  faded element already surfaces as a `color` finding with the alpha in it. A second channel would
  double-report the same cause. (And it would not have caught session 18's `opacity:0` footprint,
  which was invisible because SVG is not extracted at all.)
- **`outline`** — Figma has no outline concept, so only one adapter could ever produce it and every
  comparison would be one-sided.
- **`backgroundImage`** — a `repeating-linear-gradient` hatch has no Figma equivalent; presence-only
  comparison is possible but asymmetric enough to want its own decision.
- **`borderStyle` in `presenceIdentity`** — it would make a one-sided box's identity finer (a dashed
  and a solid box are different decisions), but it also re-keys every recorded `accepted` presence
  rule and lapses those suppressions. Separate change, separate blast radius.
- **SVG shape extraction** — the one thing that would have caught the invisible footprint. Still
  open; it needs a noise-control decision (which shapes, how `<g>`/`<path>` collapse), not a
  drive-by.

## Session 18 (2026-09-02) — the ghost, built

All in `packages/annotator/src/render.ts` (+ its test), measured on
`refdiff-compare-desktop-ghost` first because its steps contain **no text match at all**.

**What landed**, and the measurement that says so:

- **The footprint** — `ghostRect()`: the element's box padded by 4, radius 6, 1.5px dashed in the
  severity colour, filled with a 45° hatch at 0.18 on a 9px period. An SVG `rect` in `layers[side]`
  (the world layer) so it SCALES with the canvas, with the hatch as three `<pattern>`s in
  `userSpaceOnUse` units. The patterns live in their OWN `<svg id="hatch-defs">`, not in a mark
  layer: `renderMarks()` `replaceChildren()`s those and would wipe a `defs` kept there.
  `rotate(-45)`, not `rotate(45)` — SVG rotates clockwise, so +45 leans the stripes the opposite
  way from the comps' `repeating-linear-gradient(45deg, …)`.
- **The pill** — `ghostPill()`: a div in `markLayers[side]` at a constant screen size, anchored on
  the footprint's top-left corner and lifted its own height + 7 WORLD px
  (`transform-origin:0 100%; transform:translateY(calc(-100% - 7px)) scale(var(--cs))`, the comp's
  own transform). Measured against the comp at its 146% canvas zoom: surface **199×30 ↔ 199×30**,
  the hollow chip's ink **12×13 ↔ 12×13**, the label "Missing here — exists in design"
  **154×14 ↔ 154×14**, and no colour, size or typography finding left on any of them. The 7px gap
  measured 10.2 screen px at 146% on both sides.
- **The halo** — `.vmark.one-sided`: `outline:1.5px dashed <sev>` at `outline-offset:2.5px` on the
  home-side badge of **every** one-sided finding, not only the selected one. That is what the comp
  does (`outline: f.oneSide ? … : 'none'`, unconditional), and the handoff's "of the selected
  finding" was half a rule. Outline is not extracted, so no channel measures it directly — the
  pixel channel sees it indirectly (`compare-mobile`'s canvas region moved on the four haloed
  badges alone).
- **The row chips** — `.fside`: `add_location_alt` + Design only / `wrong_location` + Impl only,
  1px dashed in the severity colour, radius 999, 10px/700 at 0.04em, padding 2px 7px, gap 4,
  glyph 12px. Measured **99×19 / 86×19** against the comp's 99.4×19 / 85.6×19, on all four
  one-sided rows. The caps come from `text-transform`, because **the extractor reads the RENDERED
  text**: the comp's DOM says `Design only` and its capture says `DESIGN ONLY`. They wrap to their
  own line under a long title exactly as the comp's do — `.fhead` is `flex-wrap:wrap` on both
  sides, which is also why the app's selected row grew 134 → 160.
- **The switch** — the pill's `.gsw` (`swap_horiz` + View design / View impl) is always in the
  markup and shown by CSS only under `body.single`, which is the comp's `canSwitch === full mode`.
  It is CSS and not a render-time flag because `setLayout()` re-renders no marks, so a flag baked
  in at render time goes stale on the Split / Full toggle. Selecting a row still never swaps the
  pane by itself — the rejection stands and the test still pins it.

**Two defects that no channel could see**, both found by cropping `impl.png` at the footprint's
screen box and putting it beside the same crop of `design.png`:

1. The rect was classed `ghost`, which this file already spends on the diff lab's superimposed
   design IMAGE (`.ghost { opacity:0 }`) — so the footprint painted NOTHING while the DOM, the
   computed fill and the stroke all read correct. The classes are `.gfoot` / `.gpill` now, and the
   `.ghost` rule says what it is. A `getComputedStyle(el).opacity` probe named it in one call once
   the crop had shown there was something to look for.
2. The hatch leaned the wrong way (`rotate(45)` vs the CSS gradient's 45deg).

The footprint is invisible to the structural channel (SVG is not extracted) and its design-side
counterpart travels suppressed inside the artboard `accepted … contents: true` region, so nothing
is reported about it either way — this is the case where one crop is the whole evidence.

**The zoom-on-select divergence, trialled and left alone.** The comp's canvas reads **146%** after
the step selects `o1`; the app's reads **100%** (`text reads "100%", design says "146%"`), so
everything the canvas draws sits at a different scale on the two sides — ~70 of the desktop ghost
pair's findings have a box inside the canvas, and the pill's own residual is exactly that offset.
The rules disagree by design: the comp's `focusOn` fits the box plus 70px each side, zooming IN to
2.2×; `focusView` (`view-math.ts`) fits it into a third of the pane and then clamps `z` to
`max(current.z, minZoom)`, so it never zooms in — while its own doc says "at most what fits the box
into a third of that area", which the clamp defeats. Trialled in a separate `--out out/vc-trial`
with the comps' formula and REVERTED: `compare-desktop-ghost` 155 → **111**,
`compare-mobile-toolbar-ghost` 95 → **99** (the phone's pane insets leave the comp's 1.23× short at
1.15×). Worth ~44 findings on one pair, −4 on the other, and it changes what selecting a row does
in every pair. **Product decision — ask Mato.**

**One REGRESSION line on `compare-desktop`, and it is a pairing artefact.** `missing-element` on the
design's rail badge "6": taller app rows re-paired the column, so the design's "6" (y=787) lost the
app's "element" prop text (y=813) it had been wrongly paired with — five findings about that element
resolved in the same run. The app's own "6" badge is at y=583, **204px away**, four pixels past the
200px repeated-text cutoff. Its ledger `resolvedAt` is older than the run, and the next run came
back `+0/−0` with no regression line, exactly as SKILL.md §4 predicts for a re-pairing.

## Key facts / decisions

**The ghost spec, measured off the comps (not read off their source).** Severity colour =
`--critical #e5484d` / `--major #f5a623` / `--minor #4c9aff`.

- **Hatched footprint:** `1px dashed <sev>`, transparent background, radius 6px, and
  `background-image: repeating-linear-gradient(45deg, <sev>/0.18 0px, <sev>/0.18 2px,
  transparent 2px, transparent 9px)` — a 2px stripe on a 9px period at 45°.
- **Ghost pill:** 199×30, `1px dashed <sev>`, background `--bg1`, radius 9px, padding 5px 9px.
  - child 1, the **hollow number chip**: 18×18, `1px dashed <sev>`, background `--bg1`,
    **text in the severity colour**, `border-radius:50%`, 10px/700.
  - child 2, the **direction label**: 11px/600 in `--txt`. Exact copy:
    `Missing here — exists in design` / `Only in impl — nothing here in design`.
  - phone only, child 3: `swap_horiz` + `View design` / `View impl`, 10.5px/700, white.
- **Halo** on the home-side mark: `outline: <sev> dashed 1px` on the 28×28 number badge
  (26×26 for a comment). "Ghosts appear only for the selected finding; home-side marks get a
  dashed halo so density never doubles."
- **Row chips:** `add_location_alt` + `Design only` (missing-element), `wrong_location` +
  `Impl only` (extra-element). Row descriptions: "Element exists in the design ref but is
  absent from the impl DOM" / "Impl renders an element with no counterpart in the design ref".

**Why `steps` hard-stops.** A capture of the wrong state is worse than no capture because it
looks like a result. Same reasoning as `blank-render` and `figma-low-quality`.

**Why steps go on both sides.** A state is a state. The comp selected against the app
unselected reports "selected vs not selected" as drift; the CLI warns via `stepsOnOneSide`.

**Why the impl step is `.frow:has(.fside)`.** The app renumbers findings `f1..fn` every run,
so an id selector means "the first finding", not "a one-sided one" — the ghost would not
appear at all on a run whose `f1` happens to be two-sided.

**Source of truth pointers:** `refdiff.bindings.md` (paths, ports, baseline, traps —
READ IT FIRST), `skills/refdiff/SKILL.md` (the loop; §0 greenfield, §1a alignment, §3a
decisions), `docs/lessons-inbox.md` (the two misses and what was built for them),
`docs/plan-annotator-redesign.md` (the redesign phases and gap numbers).

## Env gotchas

- **The `pnpm dev` watcher stopped rebuilding silently mid-session** (a `git stash`/`pop` of
  `render.ts` during an A/B is the suspected cause). Two CSS fixes read as `+0/−0` delta
  because the served shell was 25 minutes stale. **Compare `dist/render.js` mtime against
  `src/render.ts` before believing any measure**, and restart the annotator — its shell is
  rendered at START.
- **No backticks anywhere in `render.ts`'s client block, comments included** — it lives
  inside a TS template literal and one backtick closes it. Broke the build once this way.
- **`pgrep -f`/`pkill -f` match the shell running them.** An `until ! pgrep -f "…cli.js"`
  loop never exits, and `pkill -f "tsc -p tsconfig"` killed the session's own shell. Match by
  PID, or on a marker the command line does not contain.
- **Pin the fixture clock before measuring** (`node fixtures/make-demo-root.ts --now`, then
  measure IMMEDIATELY, then regenerate WITHOUT `--now`). Unpinned, `library-desktop` read 41
  suppressed against the recorded 25 — pure noise. Never commit `--now` output.
- **Re-run `node packages/annotator/scripts/icon-subset.mjs` after any comp refetch** (needs
  network). A glyph missing from the 97-glyph subset renders as its NAME and every finding
  about it is noise. `--check` says whether the list is current.
- Ports on the devbox: 7378 is an unrelated annotator from another checkout; 7380 serves the
  population-registry DS run root; 7381/7382/7390 are the ones above.
- The comps hydrate `dc-runtime` from `support.js` and React from unpkg — offline runs fail
  `hydration-failed`, not silently.
