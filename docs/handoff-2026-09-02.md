## Key facts / decisions

**The ghost spec, measured off the comps (not read off their source).** Severity colour =
`--critical #e5484d` / `--major #f5a623` / `--minor #4c9aff`.

- **Hatched footprint:** `1px dashed <sev>`, transparent background, radius 6px, and
  `background-image: repeating-linear-gradient(45deg, <sev>/0.18 0px, <sev>/0.18 2px,
  transparent 2px, transparent 9px)` — a 2px stripe on a 9px period at 45°.
- **Ghost pill:** 199×30, `1px dashed <sev>`, background `--bg1`, radius 9px, padding 5px 9px.
  - child 1, the **hollow number chip**: 18×18, `1px dashed <sev>`, background `--bg1`,
    **text in the severity colour**, `border-radius:50%`, 10px/700.
  - child 2, the **direction label**: 11px/600 in `--txt`. Exact copy:
    `Missing here — exists in design` / `Only in impl — nothing here in design`.
  - phone only, child 3: `swap_horiz` + `View design` / `View impl`, 10.5px/700, white.
- **Halo** on the home-side mark: `outline: <sev> dashed 1px` on the 28×28 number badge
  (26×26 for a comment). "Ghosts appear only for the selected finding; home-side marks get a
  dashed halo so density never doubles."
- **Row chips:** `add_location_alt` + `Design only` (missing-element), `wrong_location` +
  `Impl only` (extra-element). Row descriptions: "Element exists in the design ref but is
  absent from the impl DOM" / "Impl renders an element with no counterpart in the design ref".

**Why `steps` hard-stops.** A capture of the wrong state is worse than no capture because it
looks like a result. Same reasoning as `blank-render` and `figma-low-quality`.

**Why steps go on both sides.** A state is a state. The comp selected against the app
unselected reports "selected vs not selected" as drift; the CLI warns via `stepsOnOneSide`.

**Why the impl step is `.frow:has(.fside)`.** The app renumbers findings `f1..fn` every run,
so an id selector means "the first finding", not "a one-sided one" — the ghost would not
appear at all on a run whose `f1` happens to be two-sided.

**Source of truth pointers:** `refdiff.bindings.md` (paths, ports, baseline, traps —
READ IT FIRST), `skills/refdiff/SKILL.md` (the loop; §0 greenfield, §1a alignment, §3a
decisions), `docs/lessons-inbox.md` (the two misses and what was built for them),
`docs/plan-annotator-redesign.md` (the redesign phases and gap numbers).

## Env gotchas

- **The `pnpm dev` watcher stopped rebuilding silently mid-session** (a `git stash`/`pop` of
  `render.ts` during an A/B is the suspected cause). Two CSS fixes read as `+0/−0` delta
  because the served shell was 25 minutes stale. **Compare `dist/render.js` mtime against
  `src/render.ts` before believing any measure**, and restart the annotator — its shell is
  rendered at START.
- **No backticks anywhere in `render.ts`'s client block, comments included** — it lives
  inside a TS template literal and one backtick closes it. Broke the build once this way.

  loop never exits, and `pkill -f "tsc -p tsconfig"` killed the session's own shell. Match by
  PID, or on a marker the command line does not contain.

  measure IMMEDIATELY, then regenerate WITHOUT `--now`). Unpinned, `library-desktop` read 41
  suppressed against the recorded 25 — pure noise. Never commit `--now` output.

  network). A glyph missing from the 97-glyph subset renders as its NAME and every finding
