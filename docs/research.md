# Research: reliable design-vs-implementation comparison for AI agents

Consolidated findings from four research streams (Aug 2026): the two seed
resources, the tooling landscape, practitioner workflows, and academic
literature. This document is the evidence base for `docs/architecture.md`.

## 1. The core problem is measured, not anecdotal

"The model says the implementation matches the design when it clearly
doesn't" is a universal, benchmarked failure mode of vision-language models:

- **DiffSpot** (2026, [arXiv 2605.29615](https://arxiv.org/abs/2605.29615)) —
  4,400 screenshot pairs generated by mutating a single CSS property. The
  best frontier model finds **40.7%** of true changes; every model drops
  below **23%** on the hard tier. Failure is property-dependent:
  `line-height` **4%** median recall, `border-radius` **13%**, gradients
  ≤27% — exactly the properties design QA cares about. Neither pixel-diff
  magnitude nor CLIP distance predicts what a VLM catches.
- **Eyes Wide Shut / MMVP** ([arXiv 2401.06209](https://arxiv.org/abs/2401.06209)) —
  CLIP-style encoders are trained for *semantic invariance*: visually
  distinct images can have near-identical embeddings, making color/count/
  position/text differences literally invisible to the model.
- **BLINK** ([arXiv 2404.12390](https://arxiv.org/abs/2404.12390)),
  **VLMs Are Blind** ([arXiv 2407.06581](https://arxiv.org/abs/2407.06581)) —
  elementary geometric perception (do boxes overlap, which is bigger) runs
  at ~51–59% vs ~96% human; cross-image correspondence is a failure mode
  that "resists mediation through natural language".
- **GUI grounding** — GPT-4V achieves 16.2% click-target grounding on GUIs
  ([SeeClick/ScreenSpot](https://arxiv.org/abs/2401.10935)), below 2% on
  high-res professional UIs ([ScreenSpot-Pro](https://arxiv.org/abs/2504.07981)).
  Never ask a VLM for coordinates or pixel measurements.
- **Resolution loss** — model image pipelines downscale screenshots (e.g.
  ~1456×819); a 2px border difference may not survive into the tokens.
- **Multi-image handling** — concatenating two screenshots side-by-side
  measurably *hurts* vs two separate image inputs
  ([More Images, More Problems](https://arxiv.org/html/2601.07812),
  [GSM8K-V](https://arxiv.org/pdf/2509.25160)); cross-image comparison is a
  distinct, weak skill ([MuirBench](https://arxiv.org/abs/2406.09411),
  [MMIU](https://arxiv.org/abs/2408.02718)).

**Conclusion:** the VLM must never be the diff detector or the pass gate.
Both existing harnesses (uctoinak-bmad `tools/design-compare`,
population-registry `frontend/ds/tooling/visual`) presented independently
rescaled side-by-side composites to the model — the worst-case format on
top of an already-broken premise.

## 2. The production-validated architecture: GVT

**GVT — Automated Reporting of GUI Design Violations**
([ICSE 2018, arXiv 1802.04732](https://arxiv.org/abs/1802.04732)), built
with Huawei and deployed to 1,000+ designers, compares mockups against
implemented screens at **~98% precision / 96% recall**:

1. Flatten both sides to **leaf-element lists** ⟨x, y, w, h, text, crop⟩
   (design metadata on one side, runtime hierarchy on the other).
2. Match elements with a cheap geometric assignment
   (KNN on γ = |Δx|+|Δy|+|Δw|+|Δh|); unmatched boxes become
   missing/extra-element findings.
3. Run **typed per-pair checks**: position/size deltas (~5px tolerance),
   color quantization/histograms (85% threshold), text string compare, and
   perceptual pixel diff *scoped inside the matched box* (≥20% diff pixels
   flags the pair).

Their violation taxonomy from 71 real mockup/impl pairs: layout ~40%,
resource (missing/wrong element or image) ~36%, text ~24%; **94% of
violations affect leaf components only**. Related:
[WebSee](https://viterbi-web.usc.edu/~halfond/papers/mahajan15icst-tool.pdf)
(diff-pixels → responsible DOM element via R-tree over
`getBoundingClientRect`), [GCat](https://arxiv.org/abs/1807.09440) (same
machinery as a visual-regression engine).

## 3. Which metrics correlate with human judgment

- **Design2Code** ([NAACL 2025](https://aclanthology.org/2025.naacl-long.199/),
  [arXiv 2403.03163](https://arxiv.org/abs/2403.03163)) — block-level
  decomposition (detect text blocks, match with Jonker-Volgenant
  assignment, score per-attribute). **Position (coef 0.76) and
  element-presence/block-match (0.74) correlate best** with human
  preference (79.9% prediction accuracy); CLIP 0.49, color 0.35; raw text
  similarity is *anti-correlated*. CLIP is only used with text regions
  masked out.
- **Sketch2Code** ([arXiv 2410.16232](https://arxiv.org/abs/2410.16232)) —
  simple element-type layout IoU agreed with humans **69.2%** — above the
  inter-human agreement of 65.8% (r² = 0.87). Cheap and near the ceiling.
- **MRWeb** ([arXiv 2412.15310](https://arxiv.org/abs/2412.15310)) — 14
  raters × 600 pairs: plain pixel MAE (SROCC 0.542) beat SSIM, CLIP, and
  LPIPS. No automatic metric reaches the human-human ceiling (0.640).
- **SSIM is pathological on UIs**
  ([Nilsson & Akenine-Möller](https://arxiv.org/abs/2006.13846)): flat
  fills, sharp edges, dark themes and equal-luminance colors produce loud
  false alarms and silent misses in the same image. Do not use whole-image
  SSIM as a verdict. LPIPS has no maintained JS binding and is perturbed by
  1px shifts ([ST-LPIPS](https://arxiv.org/abs/2207.13686)); DISTS's
  texture invariance forgives wrong text.

**Metric weighting for this tool:** element presence + position first,
color second (CIEDE2000 in a perceptual space), holistic embedding score
only as a tie-breaking prior — never as the gate.

## 4. What makes model feedback effective (the comprehension layer)

Evidence-backed techniques for the layer where the model *does* look:

| Technique | Evidence |
|---|---|
| **Set-of-marks**: numbered marks/boxes baked into the overlay; the model reasons about "mark 3", never coordinates | Grounding 25.7% → 86.4% ([SoM, arXiv 2310.11441](https://arxiv.org/abs/2310.11441)) |
| **Native-resolution crops per region, sent as separate images** | +20%+ on fine-grained tasks ([V*, arXiv 2312.14135](https://arxiv.org/abs/2312.14135), [MLLMs Know Where to Look](https://arxiv.org/abs/2502.17422)); marks and 1.2–3× crops each beat raw screenshots ([Interaction2Code](https://arxiv.org/abs/2411.03292)) |
| **Structured intermediates**: give the model the element tree with boxes + resolved styles from both sides; it compares data, then confirms on crops | Layout-tree intermediates beat screenshot self-refinement by a wide margin ([DCGen](https://arxiv.org/abs/2406.16386), [UICopilot](https://arxiv.org/abs/2505.09904), [LayoutCoder](https://arxiv.org/html/2506.10376)); naive screenshot-pair self-revision is near-useless (Design2Code ablation) |
| **Always attach the reference** alongside the screenshot | Single biggest accuracy lever for VLM bug detection ([Canvas study, arXiv 2501.09236](https://arxiv.org/abs/2501.09236)) |
| **Two-stage critique**: visual difference description per marked region → separate translation into code actions; multi-dimensional judging, not one score | Two-stage beat unified critique; multi-dim agreed with humans 69.5% vs 48.5% single-score ([arXiv 2604.05839](https://arxiv.org/html/2604.05839)); grounded (comment, bbox) critique format ([UICrit](https://arxiv.org/abs/2407.08850), [Google iterative critique](https://arxiv.org/abs/2412.16829)) |
| **Interactive inspection**: give the model crop/zoom/sample-pixel tools it can drive | Guided visual search outperforms one-shot viewing (V*/SEAL, [VipAct](https://arxiv.org/pdf/2410.16400)) |
| **Relative verdicts**: better/worse than the previous run | Comparative rankings are usable where absolute scores are not ([UI2Code^N](https://arxiv.org/html/2511.08195)) |
| **Loop hygiene**: bounded iterations, diminishing-returns cutoff, regression guard on previously-passing regions | Unbounded agents chase sub-pixel offsets (Kaelig: max 5 iterations, stop <2% improvement); models "forget" and break fixed regions ([FronTalk](https://arxiv.org/abs/2601.04203)); accept-only-improving revisions prevent collapse ([ReLook](https://arxiv.org/abs/2510.11498)) |
| **NL ignore-policies** for intended/dynamic deviations | [LLMShot](https://arxiv.org/abs/2507.10062); GVT manual exclusions |

## 5. Practitioner consensus

- **Anthropic guidance** ([Claude Code best practices](https://code.claude.com/docs/en/best-practices)):
  give the agent a way to verify; escalate from prompt iteration to
  deterministic Stop-hook gates and fresh-context reviewer subagents;
  "have Claude show evidence rather than asserting success."
- **The measurement-first loop**
  ([Vadim, pixel-perfect Playwright + Figma MCP](https://vadim.blog/pixel-perfect-playwright-figma-mcp/)):
  extract design values as numbers (Figma variables/MCP), measure the DOM
  (`getComputedStyle`, `getBoundingClientRect`), feed the model numeric
  deltas, not screenshots. Same conclusion in
  [claude-pixel-perfect-agent](https://github.com/maxrihter/claude-pixel-perfect-agent)
  (token extraction first "prevents 80% of false positives"; ~60% of false
  positives come from incomplete token extraction).
- **Kaelig, agent teams**
  ([design-system-components-with-ai-agent-teams](https://www.kaelig.fr/design-system-components-with-ai-agent-teams/)):
  input-quality scoring that **hard-stops** on degraded Figma extraction
  (REST fallback −0.30, unresolved tokens −0.02 each, <0.80 stops the
  pipeline) — degraded input silently makes the model fabricate tokens
  ("27 fabricated tokens passed all functional tests, rendered unstyled").
  Token-source precedence: embedded Specs YAML
  ([EightShapes Specs](https://eightshapes.com/)) > Figma variable
  bindings > docs. Isolated-context verification (the reviewer sees only
  component + spec). Surface what the tool *cannot* verify (motion, hover
  feel, designer intent) as explicit human gates.
- **State of AI in Design Systems**
  ([report](https://state-of-ai-in-design-systems.netlify.app/), July 2026,
  20 major design systems): "None of them trust generation. They check it
  mechanically." Structural coercion (tool gates, validation loops,
  deterministic scoring rubrics) over instruction. Figma MCP output is
  treated as *reference, not code generator*
  ([React Spectrum figma-to-s2](https://react-spectrum.adobe.com/.well-known/skills/react-spectrum-s2/references/guides/figma-to-s2.md));
  the flagship visual loop is Fluent UI's per-component-Storybook
  `/visual-test` skill
  ([SKILL.md](https://raw.githubusercontent.com/microsoft/fluentui/master/.agents/skills/visual-test/SKILL.md)).
  Deterministic scoring rubric example:
  [Spectrum scoring-rubric](https://react-spectrum.adobe.com/.well-known/skills/spectrum-audit/references/scoring-rubric.md).

## 6. Tooling landscape (reuse candidates)

Diff engines:

| Library | Notes |
|---|---|
| [odiff](https://github.com/dmtrKovalenko/odiff) (`odiff-bin`) | Zig/SIMD, ~6–8× pixelmatch, AA-aware, `ignoreRegions`, used by Argos and Lost Pixel |
| [pixelmatch v7](https://github.com/mapbox/pixelmatch) | OKLab+HyAB color distance, AA detection, `windowSize` density metric; zero-dep fallback |
| [looks-same](https://github.com/gemini-testing/looks-same) | ΔE CIE perceptual tolerance; the only mainstream engine emitting **`diffClusters` bounding boxes** natively |
| [@blazediff](https://www.blazediff.dev/) | JS/WASM/native cores; `@blazediff/ssim` (MS-SSIM, GMSD); **`@blazediff/agent`** is the closest prior art to this project's packaging: region boxes, side-by-side tiles, verdict.json for coding agents (MIT) — evaluate as a dependency for the pixel channel |

Systems worth studying:
[Argos diff pipeline](https://argos-ci.com/docs/diff-algorithm)
(normalize → multi-threshold passes → pixel clustering → mask + score),
Chromatic [SteadySnap](https://www.chromatic.com/features/steadysnap)
(capture-side stabilization instead of diff-side tolerance),
[Percy Visual Engine](https://www.browserstack.com/blog/introducing-percy-visual-engine/),
[Playwright toHaveScreenshot](https://playwright.dev/docs/test-snapshots)
(mask locators, animation disabling, capture-until-stable),
[Vitest visual regression](https://vitest.dev/guide/browser/visual-regression-testing)
(pluggable comparator interface).

Design-vs-implementation specifically:
[Applitools Figma](https://applitools.com/solutions/figma/) (the only
established design-as-baseline product; match levels Strict/Layout/
Content), [Uiprobe](https://www.uiprobe.io/learn/what-is-automated-design-qa-for-figma)
(property-level: Figma API values vs computed CSS, no pixels),
[DiffLens MCP](https://github.com/byzkhan/difflens) (diff overlay with
merged regions + anti-animation CSS + pinned locale),
[mcp-design-comparison](https://github.com/w01fgang/mcp-design-comparison),
[OneRedOak design-review](https://github.com/OneRedOak/claude-code-workflows/tree/main/design-review),
[figma-html](https://github.com/BuilderIO/figma-html) (DOM → Figma-node
space), [Figma Console MCP](https://github.com/southleft/figma-console-mcp)
(resolves variable bindings to token names; Kaelig's primary extraction
path).

Alignment: no off-the-shelf Node solution. Recipe: sharp normalize (known
DPR/export-scale metadata) → hand-rolled NCC / template match for
translation (~100 lines on raw buffers) → escalate to
[@techstark/opencv-js](https://www.npmjs.com/package/@techstark/opencv-js)
(ORB + RANSAC homography) only if correlation confidence is low.
Element extraction for pixels-only sides:
[OmniParser](https://arxiv.org/abs/2408.00203),
[UIED](https://dl.acm.org/doi/10.1145/3368089.3417940) — prefer metadata
boxes (Figma node tree / DOM) whenever available.

**The gap this project fills:** no OSS tool combines design-source ground
truth (Figma variables / design canvas DOM) + DOM measurement + aligned,
scoped pixel diff + agent-facing packaging in one composable core.
`@blazediff/agent` (pixels, run-vs-run) and `claude-pixel-perfect-agent`
(tokens, no pixels) are the two existing halves.

## 7. Never rely on

- A VLM comparing two raw screenshots (detection recall <41%, and its
  "matches" means "I couldn't perceive a difference").
- VLM-reported coordinates, measurements, or counts.
- Whole-image SSIM/MS-SSIM, stock CLIP similarity, DISTS, perceptual
  hashes as fidelity verdicts.
- Concatenated side-by-side images as model input.
- "N/M pairs captured" as a pass signal — a rendered 404 captures
  "successfully" (observed failure in the uctoinak-bmad harness).
- Unvalidated LLM-judge rubrics; vendor "AI visual diff" accuracy claims.
